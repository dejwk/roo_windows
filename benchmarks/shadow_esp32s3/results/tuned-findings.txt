Parameter-only legacy shadow experiment on ESP32-S3

Makerfabs MaTouch 5-inch, 800x480 RGB565; CPU 240MHz, flash 80MHz;
8MB OPI PSRAM; 16MHz RGB panel clock; zoom 100%.
Two runs per firmware, median of 14 warmed batch means per measurement.
Original six modes retain their previously recorded raw runs. The new tuned
mode uses the same board, scene cases, timing harness, and compiler settings.

Changes permitted in this experiment:
- Extent, starting alpha, and vertical offset of each of the two shadows.
- Ambient placement gains a vertical offset, with corresponding bounds.
- No change to legacy distance evaluation, integer square root, linear alpha
  calculation, precomputed alpha_step, plain a+b alpha, or bulk fast paths.
- No alpha LUT, new per-instance fields, runtime floats, or pixel-loop branches.
- Six 6-byte parameter rows in flash; default production renderer unchanged.

Geometry and algorithm interpretation:
- Original -> tuned native area: x1.380; native sampling
  time: x1.638; average time/pixel: x1.187.
- These averages include the same 2,852 opaque surface pixels, which take the
  fast return. Remaining sampled pixels: 1,116 original, 2,624 tuned, 4,544 LUT.
  Thus changing bounds also changes the mix of cheap interior and expensive
  edge/corner/transparent samples; area normalization is not pure kernel cost.
- The identical 512 exterior coordinates cost 2.014 us/pixel
  tuned versus 2.003 original and 1.702 two-LUT flash.
  This controls query count and coordinates, but geometry still affects branch
  paths and early-zero decisions. It does not isolate only alpha arithmetic.
- Two-LUT flash covers 1.351x the tuned native area and takes
  1.267x its native time. Fixed-coordinate LUT sampling is faster
  than tuned legacy. Gaussian evaluation is not inherently the dominant cost
  in these measurements; shadow footprint and bulk/branch behavior matter.
- There is no exact causal percentage assigning time to geometry vs arithmetic:
  the models have different support and fast-path eligibility. Full refreshes
  also include damage restoration, composition, and display-driver work.
- The zero-elevation control differs between linked firmware images. Treat
  small timing changes as code-layout/workload effects, not pure math cost.

- Integer model first matched existing compiled legacy samples exactly; the
  fitted model then matched compiled tuned samples exactly on this mask.
- Allowing the ambient layer to move is significant: fitting with its original
  zero offset gave 16-28% error, versus about 9-11% when both layers can move.
- Fit searches reaches 1..32px and offsets 0..16px, then refines integer alpha
  for the best continuous candidates. This is not a global-optimum proof.
- These are fitted 56/96dp references, not held-out visual tests. The hardware
  also renders menus, circles, mixed radii and outlines; those cases have no
  separate browser-reference accuracy claim. Other zoom levels are uncalibrated.
- Native-scale RGB565 host comparison: tuned-rgb565-comparison.png. RGB565
  quantization still limits faint tails, particularly on dark backgrounds.
  No dithering was added. See target RGB565 profiles in the raw run JSON.

Validation and state:
Focused tuned-mode tests check straight-edge additive/linear values, damage
bounds, zero elevation, levels above five, and scalar/bulk equality for all
five levels, sharp/rounded/mixed corners, circles and fractional outlines.
Default legacy tests and a compiled Gaussian regression also pass.
Decoration remains 84 bytes; static RAM 30,632 bytes, unchanged from legacy.
The board is left showing the tuned legacy gallery. The original full flash
backup remains /tmp/roo-shadow-review/esp32s3-before-benchmark.bin.
