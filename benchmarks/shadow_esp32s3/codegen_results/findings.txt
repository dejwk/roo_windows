Generated-code optimization review (ESP32-S3, 800x480 RGB565)

This pass follows e613ff41. The retained implementation is the compact
combination, using the platform's normal -Os compiler setting. It preserves
the two 256-byte flash LUTs and exact alpha values. No added per-instance
fields or runtime tables. Optional side/corner caches remain selectable.

Main result: the retained plain two-LUT core uses 29.2% less time per fixed
sample, 25.0% less time per tiled output pixel, and 28.0% less time for a single
level-3 widget refresh than the fresh prior-core control. Linked flash grows by
192 bytes; static RAM and Decoration size are unchanged. The side cache
still helps larger/mixed surfaces (about 6-7% here). The full corner cache
is not recommended for this workload: its small sampling advantage does
not compensate for its slower full refresh and roughly 48KB storage cost.

Retained changes:
- Reject exterior pixels before setting up fill/outline/press coverage.
- Reject fully covered/transparent corner pixels with squared thresholds;
  only the one-pixel antialiasing band needs a coverage square root.
- Reject radial shadow samples beyond the last nonzero LUT entry, before sqrt.
- Inline the small read() wrapper; unroll readColors() four samples at a time.
- Derive side-cache indices from existing edge coordinates, reducing live
  variables. The side-cache shader's entry frame drops from 80 to 48 bytes.
- Keep the original exact three-step integer Newton sqrt.

Definitions:
aa_bounds: exact squared-distance coverage rejection.
sqrt2: closer secant seed, two integer Newton divisions, exact final correction.
radial_reject: exact circular rejection inside the rectangular shadow support.
unroll4: four explicit samples per readColors loop iteration.
local_o3: O3 pragmas limited to decoration.cpp and shadow_lookup.cpp.
exterior_first: skip fill/outline/press setup outside the widget rectangle.
inline_read: force only the tiny read() wrapper inline.
cache_liveness: reuse edge coordinates for side-cache indices.
combined_o3: aa_bounds + radial_reject + exterior_first + cache_liveness + O3.
combined_unroll: combined_o3 plus unroll4.
compact: aa_bounds + radial_reject + exterior_first + cache_liveness +
         inline_read + unroll4, with the normal -Os setting.

What the generated code showed:
- Default Arduino build uses -Os. The original sampling loop calls read(),
  which calls readWithContent(), which calls coverage and shadow helpers.
  Removing wrappers/branches matters even when the shadow math is unchanged.
- CLZ already maps to nsau. min/max use target instructions where applicable.
  Source-over division by 255 already uses a reciprocal multiply and shifts;
  it is not a per-pixel integer divide. Manual reciprocal coding is low priority.
- Each original calculated radial distance uses three quou instructions.
  Reducing divisions alone was not enough: the improved seed needs extra
  arithmetic. The isolated and whole-renderer measurements confirm this.
- The side-cache shader originally has an 80-byte entry frame and spills
  original coordinates. Edge-coordinate reuse reduces it to 48 bytes.
  These are individual function frames, not a measured maximum call-stack size.
- O3 inlines many more operations. It helps the baseline renderer, but adds
  about 8.7KB of flash in the side-cache build. The compact combination adds
  only 140 linked bytes there. Static RAM and sizeof(Decoration) remain the
  same (30776 benchmark bytes and 84 bytes per Decoration).
- Optimizations do not compose additively. combined_o3 improves standalone
  sampling substantially but regresses full refresh. Its generated coverage
  call structure differs from local_o3; image layout/cache effects can also
  affect whole-firmware timings. No dynamic instruction profiler was used,
  so the exact cause of every timing difference is not claimed to be proven.

The two-division secant-seed implementation and corrected sqrtf passed an
exhaustive host check of all 2^32 inputs. Hardware kernel checks cover the
sample corpus, not all 2^32 float inputs. A bounded two-step version retains
the old seed below 2^18 and uses three steps above; the reduced domain was
checked exhaustively. An attempted 2^20 threshold failed at 262596 and was
rejected before hardware measurement. The bounded shortcut's small-input
benefit is small and it regresses larger inputs. Neither alternate was retained.

The linked sqrtf is not a single hardware square-root instruction: the S3
library uses sqrt0.s followed by a refinement sequence. It is slower here.
A cheap integer distance approximation, (123*max + 51*min + 64)/128,
was checked for image error, not benchmarked on hardware: for radius16/level3
it changes 20.4% of visible shadow RGB565 pixels over white, with a maximum
alpha error of 13/255. Across tested radii/levels the maximum is 38/255.
This was rejected for appearance; see approx_quality.json and its script.

Validation:
- All 9 targeted Bazel tests pass: shadow_lookup_test and both gradient caches
  at zoom 75, 100, 150, 200. New cases independently verify all fractional
  coverage positions, exterior composition with press/outline, and batch tails.
- 64 elevation captures are byte-identical to the original two-LUT captures.
- RGB565 edge profiles are identical in all completed full-suite captures.
- Retained core/side binaries have identical executable and rendering-data
  sections to the measured compact prototypes after formatting and guarding
  the optimizations. See retained-equivalence.json.
- GCC -fanalyzer with the test configuration was run on both translation units,
  baseline and candidate. No diagnostic in the changed shadow code. Two
  diagnostics in dependent raster-stream headers reproduce on the baseline;
  they are recorded, not asserted to be newly introduced or fully resolved.

Method and limitations:
This pass collected 4893 rendering timing batches (11 full runs and six
screening runs), plus 84 same-image kernel timing batches. Two earlier core
control runs are also archived for reference and are excluded from that total.
Each full run has 399 timing batch means (7 per metric/scene), 14 scenes,
25 refreshes per refresh batch, 150 fixed-sampling iterations, and 12 native
or tiled iterations. Screening runs deliberately stop after the first three
scenes (84 timing rows); they are explicitly marked and are not full-suite
results. One partial USB line interrupted a screen; the reader was fixed to
accumulate complete lines, and that experiment was rerun. Only complete
captures are included in aggregates.

Sampling metrics measure ARGB decoration output. RGB565 conversion/blending,
framework work and PSRAM output are included in refresh1/refresh12. Refresh
pixel counts only describe logical widget area; they are not a count of all
written pixels, so refresh time is deliberately not normalized per pixel.
This is warm steady-state performance at 240MHz CPU / 80MHz flash, with the
16MHz display running. Small differences can reflect compiler layout and
cache behavior; cold-cache and mixed-application workloads are not covered.

Reproduction:
Use a separate worktree at e613ff41, apply the experiment's change.patch, then
build/run benchmarks/shadow_esp32s3 with its double_sides environment; *_core
experiments use double_optimized. Existing capture_serial.py and
analyze_hardware.py provide full-suite capture/aggregation. Benchmark scripts
can use PYTHONPATH=benchmarks/shadow_esp32s3/offline_tools to keep installed
pioarduino Python dependencies. Do not apply several single-experiment patches
on top of each other: combined experiments have their own complete patch.
The kernel experiment's patch adds the 'k' command to the baseline sketch.
Standalone numerical check sources and captured compiler output are retained.

Remaining opportunities, not measured in this pass: hoisting all row-constant
geometry out of arbitrary-pixel sampling, profiling RoundedDecoration/Clipper
composition, and explicit instruction/data-cache placement under realistic
mixed UI workloads. These results identify a faster measured configuration;
they are not a claim of globally optimal code for every target or workload.
